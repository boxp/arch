## Guaranteed

- K0 withholds the fixed source table: environment, SSH, cloud and CLI credential files, kubeconfig, private-key extensions and token files (any word ending in `token`, a `tokens` word with a suffix or extension, or a `tokens` path element; a bare plural such as `max_output_tokens` is a counter word); and the listed AWS, gcloud, Azure, kubectl, oc, Vault, 1Password, Docker, Helm, Git and environment-dump commands. The first reason propagates to later bodies and the session lineage, including later results that a known-format mask would otherwise let through.
- K0 is judged where a tool reads or runs something (BOXP-428 TD-12): the path arguments of a tool (`file_path`, `path`, `notebook_path`, `filename`, `file`, `target_file`) and its command arguments (`command`, `cmd`, `script`, `code`, including a Codex `["bash","-lc",script]` vector). Text that a tool only carries is not a source: Edit/Write content, descriptions and prompts, the body of a heredoc fed to a program that is not an interpreter (`delegate.py run <<EOF`, `cat > file <<EOF`), an option value with spaces (`--note "..."`, `-m "..."`), `echo`/`printf` text and a `grep`/`rg` pattern. Command substitutions inside such text (`echo "$(cat .env)"`, and in the body of an unquoted heredoc `cat <<EOF` with `$(cat .env)` or `` `printenv` ``, which the shell expands; a quoted `<<'EOF'` body is literal) and `-c` scripts of a shell or interpreter, including a one-word script (`bash -lc '...'`, `bash -c 'printenv'`, `sh -lc env`), are still judged, and a heredoc read by an interpreter (`python3 - <<EOF`, `ssh host bash <<EOF`) is judged as code. Only an unquoted, uncommented `<<TAG` is a heredoc operator: `echo '<<EOF'`, `echo "x <<EOF"`, `echo a # <<EOF` and `echo \\<<EOF` start no heredoc, so the lines after them are judged as commands (quote state carries over lines; an operator it misses only makes its body judged as commands). The environment is a source when it is dumped (`env`/`printenv` with nothing to run; `env` with assignments or options before a command runs that command, so `env LANG=C printenv` and `env -u HOME printenv` are dumps and `env LANG=C sort a.txt` is not; `env -S` is withheld, `set`/`export`/`declare` with nothing to set or `-p`/`-x`, `os.environ`, `process.env`, `getenv()`, `/proc/*/environ`, `.items()`/`.keys()` of them, and `.copy()` of them unless the copy is only assigned or passed as an argument such as `env = os.environ.copy()` / `run(cmd, env=os.environ.copy())`; `print(os.environ.copy())` is a dump) or when a variable with a secret name is printed on the same line (`print(os.environ['GITHUB_TOKEN'])`); reading one variable (`os.environ.get('LAYOUT')`, `process.env.HOST`, `token=os.environ['MCP_TOKEN']` passed to a client) is not. `kubectl`/`oc` is a source when `secret`/`secrets` is a word of the same pipeline segment, not when a later `grep -v secret` filters its output. The remote command of `kubectl exec ... -- cmd` / `oc exec ... -- cmd` is judged like a local one, so `kubectl exec pod -- printenv GITHUB_TOKEN`, `-- env LANG=C printenv` and `-- sh -c 'printenv'` are dumps and `kubectl exec pod -- ls /app` is not. A token file without an extension or a directory (`mytoken`, `access_token`) is a source in a reading position: a path argument, an operand of a program that is not a mention program (`ls`, `grep`, `echo`, `git add` ...), `< file` or `NAME=file`. A command text over 256 KiB is not parsed and is withheld.
- Lineage evidence from a header, bearer or URL-credential hit (`known_format_in_tool_output`) counts unless its value is a documentation placeholder (BOXP-428 TD-12): the value after `Bearer`/the header name (and its scheme) or the URL password is empty, starts with `$`, `<`, `{`, `%`, `*` or `[`, is an upper-case name without digits (`YOUR_API_TOKEN`), a lower-case word of at most 12 letters (`bearer token.`), surrounding punctuation ignored, or is `xxx`, `...`, `password`, `pass`, `pwd`, `secret`, `key`, `token`, `api_key`, `access_token`, `changeme`, `your...`, `my...pass...`, `example...`. Documentation such as `Authorization: Bearer <token>` is masked in place and does not withhold what follows. A JWT, AWS/Google/Telegram key or private key is evidence as before. A provider key is evidence unless what follows its prefix is shorter than 8 characters or an ordinary identifier of lower-case words joined by `_` or `-`: a prefix on an ordinary name (`npm_config_cache`, `sk-inet`) is masked in place and does not withhold what follows (BOXP-428 TD-12).
- K1 masks provider keys, AWS and Google keys, Telegram values, JWTs, bearer and header values, URL credentials, private keys, secret-name assignments, environment entries and values, flags, CLI passwords and XML elements. Lines with a secret word and their neighbours are masked.
- Lineage withhold after a tool result (`known_format_in_tool_output`) is triggered only by shapes that are credentials by themselves: private keys, Authorization/Cookie headers, URL credentials, JWTs, bearer values, provider/AWS/Google/Telegram keys, and the exporter's own environment values. Name-based hits (secret-name assignments, environment entries, flags, CLI passwords, XML elements) mask the value in place and do not withhold what follows: they also match ordinary code and logs such as `TOKEN_FILE=/work/x`, `token = os.environ[...]` or `credentials: 'same-origin'`, which withheld whole runs in production (BOXP-428, 2026-11-07).
- A value named by a name-based hit (assignment, environment entry, flag, CLI password, the text of an XML element whose tag names a secret such as `<password>x</password>` including encoded tags; each line of a block value or element) anywhere in the run's bodies is masked in every field of the same run, including its JSON/percent/HTML escapes, and the final guard checks for it too. So a bare restatement such as a reply `it is <value>` after a tool result `password: <value>` is not sent. A named value of 1-3 characters (`password: q7z`, `"auth": 38`) is pinned as a whole word: it is masked wherever it stands alone (letters, digits and `_` on neither side; an escape such as `\n`, `\u0020` or `%20` before it counts as a boundary), not inside longer words. Before BOXP-428 TD-12 such a value withheld the whole lineage, and in production the triggers were test logs (`PASS: old`) and config files (`same_site_cookie_attribute = "lax"`), which hid most runs. A named value longer than 256, or more than 64 in one text, cannot be masked: in a tool result it withholds the later bodies of the lineage (`known_format_in_tool_output`). A value that cannot be a credential by its shape is not a value: no letter or digit (`${KEY:-}` leaves `-`, `==`), a template or expression start cut off by the value scan (`${{ secrets.X }}`, `{{ .Values.x }}`, `{% ... %}`), or a grep -n location (`file.yaml:4:`, where the name is a file name with an extension). A printf directive or digits with a colon can be a real password, so `password: %d` and `password: 1234:` are pinned (`%d` as a whole word; a later `%d` is over-masked). Over 256 distinct named values in one run fail the run closed (`pinned_values_over_limit`). A value starting with `$` (`password: $hunterhorse`, `${DB_PASSWORD}`) cannot be told from a variable reference, so it is pinned like any value (a later `${DB_PASSWORD}` is over-masked); a `$X` form shorter than 4 characters does not withhold, since it is most likely a reference. Redaction placeholders, settings (`PASSWORD_REQUIRED=true`) and self-closing tags are not values; a secret element after a self-closing one (`<password/><password>x</password>`) is still read. A quoted value ends at the same quote token, including serialized quotes (`\"`, `\u0022`, `&quot;`, `&#34;`, `&#x22;`, `&apos;`, `&#39;`), so `password: &quot;x&quot;` pins `x`. A quote token preceded by an escaping backslash run does not end the value: `password: "a\"b"` pins `a\"b` and its decoded form `a"b`. A quote after an escaped backslash does end it: `password: "hunterhorse\\"` pins `hunterhorse\\` and its decoded form `hunterhorse\` (a quote with n backslashes, `\"` inside a JSON string, ends the value when the run before it is a multiple of 2(n+1)). A value captured with HTML entities or JSON escapes (`password: &quot;a&amp;b&quot;`, `\u0026`) is pinned in its decoded form too (up to 3 nested layers), so the plain restatement `a&b` is masked. An unquoted value ends at whitespace, `,;}]`, a quote or a quote/line escape (`\"`, `\u0022`, `\n`, `\r`, `\t`); any other backslash is part of the value, including a leading one (`password: \mysecret123` pins `\mysecret123`; its JSON form `\\mysecret123` pins both forms). A CLI password (`curl -u user:x`, `--user`, `mysql -px`, `sshpass -p x`) is one shell word: a quoted value runs to its matching quote, including serialized quotes, so `sshpass -p 'apple orchard'`, `mysql -p"a b"` and `curl -u 'admin:a b'` mask and pin the whole value `apple orchard`, not only the part before the space; the flag is matched case-insensitively for both masking and pinning (`curl --USER admin:x`, `-U`, `sshpass -P x` pin `x`; `mysql -P <port>` is over-masked); an unclosed quote runs to the end of the line, including the whole-word form `curl -u 'admin:a b` (over-mask, and a long remainder withholds the lineage). An unquoted value (a flag value `--password x` too) does not end at a backslash-escaped space: `sshpass -p apple\ orchard` masks the whole word in place and pins both the written form `apple\ orchard` and the shell-decoded password `apple orchard` (the JSON form `apple\\ orchard` too). Other shell forms (`$'...'`, concatenated quoted parts) are the accepted residual (section 2). An environment entry (`{"name": "API_SECRET", "value": "x"}`) is read with any serialized quote around its `name`/`value` keys (`&quot;value&quot;:`, `\u0022value\u0022:`), so an HTML- or JSON-encoded entry pins `x` too. A list or object value (`password: [a, b]`, `{"api_key": ["a", "b"]}`, `secret: {primary: a, backup: b}`, an object nested in a list `password: [{primary:a}]` (an unquoted `key:value` token with no space after the separator pins both the whole token and its value inside a list), the flag form `--password [a, b]`, an environment entry `{"name": "API_SECRET", "value": ["a", "b"]}` in either key order, nested brackets included) is masked in place as a whole and every element is pinned, not only the text up to the first delimiter; object keys are names, not values. An unclosed bracket runs to the end of the text (fail closed: more than 64 elements, or a long unscanned remainder after 256 tokens, withholds the lineage). An unclosed secret-named tag is masked to the end of the text and its text counts as named values, so a long remainder withholds the lineage (fail-closed over-withhold).
- The queue and spool receive masked, final-guarded spans. Scan failures and tool outputs over 1 MiB fail closed.

## Not guaranteed (accepted residual, Owner decision)

Plain values without a secret word or format nearby; a 1-3 character named value restated inside a longer word; a password made only of punctuation; a model repeating a value far from its source without its name or format (other than the exact named values above); a named value restated in another run or only partly, or transformed (Base64, hex, reversed, spelled out); a short (under 4 characters) named value in a prompt or reply; unknown transforms; arbitrary shell spellings of the same command (including a source read through a variable, `f=.e; cat ${f}nv`, a quoted path with spaces given as an option value, or a secret-named environment variable printed through another variable or line); a credential whose value has a placeholder shape listed above, such as an upper-case-only value without digits (still masked in place, but it does not withhold what follows); and secrets in the Owner's request without a format.
