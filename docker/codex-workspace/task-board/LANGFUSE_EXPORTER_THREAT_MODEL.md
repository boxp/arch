## Guaranteed

- K0 withholds the fixed source table: environment, SSH, cloud and CLI credential files, kubeconfig, private-key extensions and token files (any word ending in `token`, a `tokens` word with a suffix or extension, or a `tokens` path element; a bare plural such as `max_output_tokens` is a counter word); and the listed AWS, gcloud, Azure, kubectl, oc, Vault, 1Password, Docker, Helm, Git and environment-dump commands. The first reason propagates to later bodies and the session lineage, including later results that a known-format mask would otherwise let through.
- K1 masks provider keys, AWS and Google keys, Telegram values, JWTs, bearer and header values, URL credentials, private keys, secret-name assignments, environment entries and values, flags, CLI passwords and XML elements. Lines with a secret word and their neighbours are masked.
- Lineage withhold after a tool result (`known_format_in_tool_output`) is triggered only by shapes that are credentials by themselves: private keys, Authorization/Cookie headers, URL credentials, JWTs, bearer values, provider/AWS/Google/Telegram keys, and the exporter's own environment values. Name-based hits (secret-name assignments, environment entries, flags, CLI passwords, XML elements) mask the value in place and do not withhold what follows: they also match ordinary code and logs such as `TOKEN_FILE=/work/x`, `token = os.environ[...]` or `credentials: 'same-origin'`, which withheld whole runs in production (BOXP-428, 2026-11-07).
- A value named by a name-based hit (assignment, environment entry, flag, CLI password, the text of an XML element whose tag names a secret such as `<password>x</password>` including encoded tags; each line of a block value or element) anywhere in the run's bodies is masked in every field of the same run, including its JSON/percent/HTML escapes, and the final guard checks for it too. So a bare restatement such as a reply `it is <value>` after a tool result `password: <value>` is not sent. A named value shorter than 4 characters, longer than 256, or more than 64 in one text cannot be masked without blanking ordinary words: in a tool result it withholds the later bodies of the lineage (`known_format_in_tool_output`). Over 256 distinct named values in one run fail the run closed (`pinned_values_over_limit`). References (`$TOKEN`, `${DB_PASSWORD}`), settings (`PASSWORD_REQUIRED=true`) and self-closing tags are not values; a secret element after a self-closing one (`<password/><password>x</password>`) is still read. A quoted value ends at the same quote token, including serialized quotes (`\"`, `\u0022`, `&quot;`, `&#34;`, `&#x22;`, `&apos;`, `&#39;`), so `password: &quot;x&quot;` pins `x`. A quote token preceded by a backslash is escaped and does not end the value, as in the in-place mask: `password: "a\"b"` pins `a\"b` and its decoded form `a"b` (a value whose last character is an escaped backslash, `"a\\"`, runs on to the next unescaped quote: over-mask). A value captured with HTML entities or JSON escapes (`password: &quot;a&amp;b&quot;`, `\u0026`) is pinned in its decoded form too (up to 3 nested layers), so the plain restatement `a&b` is masked. An unclosed secret-named tag is masked to the end of the text and its text counts as named values, so a long remainder withholds the lineage (fail-closed over-withhold).
- The queue and spool receive masked, final-guarded spans. Scan failures and tool outputs over 1 MiB fail closed.

## Not guaranteed (accepted residual, Owner decision)

Plain values without a secret word or format nearby; a model repeating a value far from its source without its name or format (other than the exact named values above); a named value restated in another run or only partly, or transformed (Base64, hex, reversed, spelled out); a short (under 4 characters) named value in a prompt or reply; unknown transforms; arbitrary shell spellings of the same command; and secrets in the Owner's request without a format.
