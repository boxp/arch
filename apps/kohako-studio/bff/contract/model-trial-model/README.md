# モデルの試行の記録のモデル（BOXP-706）

コハコの家の「家の会話だけで別のモデルを回数・期限つきで試す」仕組みについて、試行の記録（`model-trial.json`）の決まりを仕様から起こした Lean のモデルです。実装の写しではありません。
仕様は Obsidian の `Projects/kohako-home/model-trial-spec.md`（spec_feature: `kohako-home-model-trial`）の「記録と決まり」。

## 決まり（1 文）

試行が早く終わる側の変更（回数 +1、失敗 +1）は、外へ作用する前に書く。試行が続く側の変更（失敗を 0 に戻す・先に足した 1 を返す）は、結果が分かった後に書く。

モデルの状態は、保存された記録（`turns`・`streak`・`inflight`・終了）、メモリの上だけの終了、再起動をまたいだか、会話が待っている発言。
出来事は、発言を送る（期限の前後・書き込みの成否）、結果が分かる（失敗・成功・停止・不明 × 書き込みの成否）、再起動（最後の発言を追跡し直す・しない）。

## 仕様の規則と定理の対応

| 仕様の規則 | 定理 |
| --- | --- |
| 指定を付けるのは、終了しておらず（メモリの上だけの終了も含む）、回数が残り、書き込みが成功した時だけ | `route_needs` |
| 保存された終了は戻らない | `ended_stays` |
| どの出来事の後も: 指定を付けた run の数 ≤ 保存された `turns` ≤ 上限、保存された `streak` ≥ 実際に続けて失敗した回数（結果を数える前の発言があれば、さらに 1 以上多い） | `safe_init`・`safe_step`（`Safe`） |
| 指定を付ける時、実際に続けて失敗した回数は 2 未満 | `route_real_lt` |
| 指定を付けた run の数は上限を超えない | `routed_le_max` |

`safe_step` は前提 `legal` の下で成り立つ: 同じ発言の結果は、何度確かめても同じ（再起動をまたいだ後は不明に変わりうる）。

## 実装との対応

- `bff/src/model-trial.ts` の `planTake`・`planSettle` がモデルの同名の関数、`commit`（書けた時だけメモリへ反映、書けなければメモリの上で終了）がモデルの `commit`、`restore` がモデルの `restart`。
- `bff/src/model-trial.test.ts` の「モデルの並び」のテストが、`cases.txt`（上限 3 で長さ 5 まで・上限 1 で長さ 4 までの出来事の並び 8,796 本と、各並びの後の「指定を付けたか・保存された記録・メモリの上の終了」）を実装に流して照合する。
- `cases.txt` の 1 行: `上限 並び 指定 turns streak inflight 保存された終了 メモリの終了`。並びの記号は T=発言、Tx=発言（書き込み失敗）、Tl=発言（期限の後）、F/D/C/U=結果（失敗・成功・停止・不明）、Fx/Dx=結果（書き込み失敗）、R=再起動（最後の発言を追跡し直す）、L=再起動（追跡しない）。

3 つの主張は別です: 仕様が正しい / モデルの証明が成り立つ / 実装は、列挙した並びの上でだけモデルと一致した。

## 検査と生成

```sh
lean ModelTrialModel.lean                     # 証明の検査
lean --run ModelTrialModel.lean > cases.txt   # 出来事の並びの生成
```

CI: `.github/workflows/test-kohako-model-trial-model.yml`（証明・sorry/公理なし・`cases.txt` が生成結果と同じ）。照合は bff の unit test（Docker build 内）で常に走る。

## 省いたもの

- 実際の並行。操作を 1 本の待ち行列で 1 つずつ行うことは、モデルではなく unit test（同時の take で 1 回目の書き込みだけ失敗）で確かめる。
- 期限は「過ぎている・いない」の 2 値、終了の理由は「終了している・いない」だけ（理由は例の unit test で確かめる）。
- 失敗と分かり、書き込みに失敗して落ち、再起動後に本人が止めた時（仕様では数えないが、前提 `legal` の外）。
- 打ち切った書き込みが後から終わり、新しい記録を古い内容で上書きすること。記録のファイルが消えること。BFF が 2 つ以上動くこと。
- 会話のどの発言に付けるか、Hermes が実際にそのモデルで動かしたか。
- 並びの生成は、発言を「待っている発言が無い時」だけ、結果を「待っている発言がある時」だけに限る（家の会話は同時に 1 つの発言しか受け付けない）。定理はこの限定なしで成り立つ。
