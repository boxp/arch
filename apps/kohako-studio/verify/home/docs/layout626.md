# layout626.mjs（BOXP-626）

`layout626.mjs`（BOXP-626）は BFF を完全にモックし、発言前後の場面替わり（くつろぎ→おしゃべり→8 秒超の作業中（上半身の枠）→返答）と画面サイズの変更（PC は 1200×800 / 1000×700 / 800×600 / 1440×900、スマホは横向き⇄縦向き）で、コハコと背景が時間とともにどう変わるかを実ブラウザで確かめます。CDP の screencast で描画された全フレームを集め、静止画 1 枚ではなく時間変化で判定します。

- 点滅: 48×30 の格子の輝度で、あるフレームだけ前後と逆向きに大きく（18 以上）変わって戻るセルを数える。コハコの見える範囲（直前 0.6 秒の範囲を含む）の外（背景・文字）と中に分けて `result.json` に残します。swiftshader での取得は 15〜20fps で、まばたき・口の動き・リサイズ後に動く月窓も拾うため合否には使わず、修正前後の比較に使います（修正前は作業中から戻る時に一瞬小さく描かれて 1 フレームで 26 セル）。
- 急な飛び: 画面サイズを変えた直後（0.4 秒）を除き、隣り合うフレームの平均輝度差の最大が 12 未満であること（修正前は作業中への切替で枠だけが即時に替わり、20 前後の飛びが 2 回続いた）。
- リグ canvas の作り直し: 場面・形・枠が替わった後 0.6 秒の間に、リグの canvas の大きさが変わる回数が 1 回以下であること（修正前は箱の CSS 遷移の間、毎フレーム作り直していた）。
- 写し: PC の作業中への出入り（全身⇄上半身）では写し（`.morph-ghost`）で移し、終わると残らないこと。画面サイズの変更（リサイズ・回転・キーボード）と `reduce`（OS の reduced-motion）では写しを使わず即時に切り替えること。

`node layout626.mjs <build の dist> <出力先>`（Playwright 1.56.1、token 不要、`ONLY=pc,mobile,reduce` で絞れます。`PW_WS=ws://host:port/` で起動済みの Playwright サーバーへ接続できます。`BASE=http://kohako-studio.kohako-studio.svc` で配備版の画面を開けます（API は同じくモック）。`EXPECT=0` は判定せず測定だけ行います（修正前の build との比較用））。失敗があれば終了コード 1 で、`result.json` に測定値、点滅・大きな飛びのあったフレームの前後を `<出力先>/<項目>/` に保存します。

headless の swiftshader（GPU なし）での測定です。実機 GPU のメモリ逼迫による背景タイルの描き直しはこの環境では再現できないため、canvas の作り直し回数を代わりの指標にしています。
