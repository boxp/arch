# reauth523.mjs（BOXP-523）

BFF をモックして PC（1280×800）と mobile（412×915）で実行する。a〜d は認証切れ時の手動再読み込み、通常の再接続、再認証失敗時の自動再読み込み防止、控えの照会を確認する。e〜h は控えと同文の草稿・送信待ちの復元、満杯時の退避、控えを入力欄に写さないことを確認する。i〜k は初期化中の手入力を失わないことを確認する。l・m は照会失敗後の同文入力を新しい発言として一件残し、控えの受付番号で重複 POST しないことを確認する。n は再読み込み後も認証できない画面で別の文を入力して再度押しても、前回退避した草稿・送信待ちを上書きせず両方戻すことを確認する。o は前回退避分と今回の入力の合計が上限を超えて確認を取り消しても、前回退避した分を消さず、その後の再読み込みで戻すことを確認する。p は受理未確認のまま新しい発言を送り照会が 401 になったとき、再認証用の再読み込みボタンへ切り替わり（控え・送信待ちは残し POST しない）、押すと再読み込みすることを確認する。

ビルドを `SITE` の `kohako/` に置き、Playwright 1.56.1 で `node reauth523.mjs <out>` を実行する。結果は `result.json` に保存し、失敗時は終了コード 1。

2026-11-15 の検証では新版は PC・mobile とも a〜m が全件成功。p 追加後は新版 a〜p 全件成功、旧版 91694c7378 は p のみ両画面で失敗（照会 401 でも再接続ボタンのまま）。その後 o を追加し、新版は a〜o 全件成功、旧版 e8a70b32cd は o のみ両画面で失敗（取消で前回退避分が消える）。n 追加時は新版は a〜n 全件成功、旧版 4a30ce18ab は n のみ両画面で失敗（前回退避の草稿が新しい入力で上書き）。旧版 c48aef5886 は両画面で a〜f・h〜k が成功し、g は旧仕様の確認ダイアログで再読み込み待ちがタイムアウト、l・m は手入力の同文が送信待ちに残らず失敗した。
