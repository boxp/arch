## 仮説と確認

`layers.jpg` は v10k 入力 layout と v11b 入力 layout の face、hair_front、左右の側髪、およびそれらの合成を同じ座標・倍率で表示する。元 face に前髪、頬脇の髪、顎線が含まれ、v11b の face は肌とキットの顎線に置換されている。前髪と側髪の切断端が v11b の合成で頬脇に現れる。これは仮説を支持する画像上の観察であり、動的メッシュ上の全ての段差の原因が一意に確定したわけではない。

## 実装と再現

元 layout `/home/boxp/b441work/full10h/build/layout` を別ディレクトリにコピーし、Pillow・NumPy・OpenCV がある環境で `LAYOUT` にそのコピー、`KIT=/home/boxp/b441work/td-kit/gen` を指定して `prepare.py` を一度実行する。元 layout を直接変更しない。元 face の矩形と RGBA を 2 倍密度に拡大して土台にし、肌色の最大連結成分の内側に限り、距離 6 px の保護領域と 12 px のフェザーを設けてキットの顔を合成する。非肌画素への重みはゼロであることを検査する。髪と顎線を元画像から保持し、キットの顎線は使わない。肌の RGB 差の中央値と、境界に近い低周波差で色を合わせる。キットの顔 warp は scale .3205、tx 372.1、ty 67.0 のまま。目の全画像は v11b と SHA-256 が一致した。元 face の目元線も保持するため、キットの目と並んで見える細線が残る。

口は暗い線画素を元 layout の閉口レイヤーの暗い画素の中央値 RGB (122,83,79) に置換し alpha を保持する。赤い口内や明るい歯を除外し、閉・中・開の各行に同じ処理をする。閾値と補間により線の全画素を原画そのものにしたことまでは保証しない。

`build.sh` には準備済み `INPUT_LAYOUT`、SHA-256 `4a2aa4a9484733c6372186e4b7267bd1f631bd3d486971f34aed47768a0d0b84` の `SOURCE`、v10k anchor.patch 適用済み psd2live `6fe868a20c7bf12586fa8ce0a05982f099faa865` の `P2L`、独立した `OUT` と `GRADLE_CACHE` を渡す。v11b の入力と出力の重なり検査、一意名、MCP と export の共通環境、MCP の `--log-driver none` を維持した。MCP import/export は成功。Idle / Talk の builtin seed は失敗したが motion modifier は生成された。

## 担当(Opus)の最終判定

未受入の比較候補（v11b より明確に改善）。比較画像 `static.jpg`・`cheeks.jpg`・`eye.jpg`・`mouth.jpg` を目視した。

- 改善: v11b の頬の階段状の段差・切れ込み・矩形の段は静止と AngleX ±20 / AngleZ ±10 で消え、顔の輪郭と顎は v10k に戻った。キットの鮮明な目、3 状態の口（0.05 刻みで二重線なし）は保持。閉口線の黄緑は茶色系になった。
- 新しい問題: 両目の目尻の外側に暗いにじみがあり、閉眼（0.10 以下）では目尻の横の影として目立つ。元 face に残る v45 の目の周りの暗い画素が肌マスクの外（非肌）として残り、キットの肌で上書きされないためと考える（未検証）。
- 残件: 目 0.60 の灰色の重なりと 0.15→0.10 の急変（v11b から継続）、開口は原画よりやや小さい、v10k から継続する髪脇のマゼンタ露出（首の傾きの大きい姿勢）。
