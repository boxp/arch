**担当自己評価: 未受入、比較用。** 肩下の回転ずれは改善したが、AngleZ で左右の新規 G と三つ編みの反転三角形が残る。Owner の受入判定ではない。Studio の既定は v45 のまま。

## 確定事項と再現

v10j を指定 layout と psd2live `6fe868a20c7bf12586fa8ce0a05982f099faa865` + `braid-anchor.patch` から再構築し、SHA-256 `420551b1d95b824b11c9fa667d070e6de9794b390804b0ac2d7e1bb25e26088b` が既存 p2lrt と一致。掲載 v10k の SHA-256 は `2e9377ddd7ed5ff427886ab31caa170e39af5244db13a1e4483bfe519214cb5e`。

`anchor.patch` は v10j を含むクリーンコミット用パッチ。案1は既存の顎から肩への smoothstep と頭支点を共有し、両ワープを24行、AngleZ のキーを −30/−20/−10/−5/0/+5/+10/+20/+30 とした。各キーの cos/sin による逆回転を維持し中間角の線形補間誤差を減らす。MCP と export の両方に `P2L_SHARED_BRAID_BACK=1` と既存の `P2L_BRAID_ANCHOR=1`, `P2L_BACKHAIR_ANCHOR=1`, `P2L_BACKHAIR_FX=15`, `P2L_BACKHAIR_FY=-6`, `P2L_BACKHAIR_SHOULDER_Y=455` を指定。`build.sh` はレイアウトと出力が重なると拒否する。MCP は `--log-driver none`。

実ソースでは支点は共通の `faceRig.centerX, mouthLineY` を canvas に変換した位置。生成済み head bone の head は canvas (571.975, 359.5) で、`SkeletonAutoBuilder` は同じ回転支点を使う。両者の遷移開始は `faceFrame.bottom`（背景資料の概算 y≈345）、終端は設定値 y=455。v10j でも終端は環境変数により 455 であり、「終端値の違い」が主因とは断定できない。v10j は後ろ髪8行、三つ編み12行で、それぞれ異なる bounds を持つ。今回の共通行数でも格子の絶対位置までは一致しない。

案2は `hidden-coverage.py` で canvas y=340..450 に限り、rest で完全不透明な三つ編みから3px内側の領域だけ背後を補った。11,291 source pixels を追加、案2の −10° G は案1の157から76へ減った。しかし案1との rest マゼンタ RGB 差が **12,719 / 930,180 px** あり、元の見た目不変条件に反するため不採用。案2は掲載 p2lrt に含まない。案1と v10j の rest 差も **395 / 930,180 px** で、完全一致ではない。
