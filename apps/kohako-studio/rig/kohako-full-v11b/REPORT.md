## 実装と再現

v11a の silhouette は使わず、顎の描線を画像上で測った座標から平滑な切断線を作り、顔の矩形を横に広げた。顔の上端は前髪の内側で切り、頭上の肌色露出を避けた。既存の前髪、後ろ髪、首、身体は変更していない。RGB を alpha 乗算して INTER_AREA で縮小し、残る位置合わせは INTER_LINEAR で行い、最後に alpha 除算する。開眼の白目・虹彩・線は高解像度でソフトマスクを作り、線を太らせてから同じ縮小処理に通す。緑が赤・青の最大値を超えないよう抑制した。口の中・開状態は口角と上唇線を固定し、下部のみそれぞれ 1.45、1.8 倍に伸ばした。各行を個別に位置合わせしていない。目と口の短区間の opacity 切替は v11a のまま。

再現には `/home/boxp/b441work/full10h/build/layout` を新しいディレクトリへコピーし、Pillow・NumPy・OpenCV のある環境で `LAYOUT` にそのコピー、`KIT` に `/home/boxp/b441work/td-kit/gen` を指定して `prepare.py` を一度実行する。元 layout に直接実行しない。`build.sh` に準備済み `INPUT_LAYOUT`、SHA-256 `4a2aa4a9484733c6372186e4b7267bd1f631bd3d486971f34aed47768a0d0b84` の `SOURCE`、v10k anchor.patch 適用済み psd2live `6fe868a20c7bf12586fa8ce0a05982f099faa865` の `P2L`、独立した `OUT`、`GRADLE_CACHE` を渡す。入力と出力の重なり検査、一意名、MCP と export の共通環境、および MCP の `--log-driver none` を維持した。

## 比較と残件

Chromium / SwiftShader、静止・状態は DPR 2、上半身、behaviors 停止。原画はラスタ画像で描画条件が完全に同一ではない。状態は 0.05 刻み、中点 0.60 / 0.135 を別途掲載。Blink は behaviors を切り、Blink クリップを 1/60 秒ずつ進めた値と、6 Hz の画面を採取した。実時間の描画落ちを含む通常動作の見え方は別途確認が必要。

同一軌道動画は v10k と v11b を 20 秒、8 fps で同一パラメータに設定し、目は開、口は閉。自然動作は待機・考え中・発話を実時間で採取し 15 秒に配置しており、キャプチャ速度によって短い変化を見逃しうる。

`web/public/kohako/live2d/compare/kohako-full-v11b-*` に `static.jpg`、`eye.jpg`、`eye-detail.jpg`、`eye-midpoints.jpg`、`blink.jpg`、`mouth.jpg`、`mouth-detail.jpg`、`poses.jpg`、`normal-pair.mp4`、`contact.jpg`、`natural.mp4` を掲載。生のキャプチャ JSON は含めない。

### 観測結果と自己評価

- 静止比較では、v11a の多角形 silhouette を使わない結果、左頬の切れ込みは軽くなり、輪郭はキットの線に近づいた。一方で顎はまだ尖って見え、顔色と横長の目は原画・v10k と異なる。初回の顔矩形拡張では前髪の上に肌色が出たため、上端を隠れる位置に収めて再ビルドした。修正版の静止画像ではその帯は見えない。
- 目の線は v11a より連続して見えるが、拡大すると虹彩とまつげの段差・細かな粗さは残る。0.60 と 0.135 の中点では灰色の重なりが明瞭で、0.15→0.10 の切替も急なまま。短区間を変更していないため、これは既知の残件。
- 閉・中・開の口は識別でき、開口は v11a より大きい。0.05 刻みのシートでは目立つ二重上唇線は見えないが、切替区間の全点を検証したわけではない。despill 後も拡大すると口線に黄緑寄りの細い色が残り、完全除去は未達。
- 9 姿勢の頭部 ROI（device pixel x=280..559、y=60..399）で、v11b がほぼ純マゼンタかつ v10k がそうでない画素は rest、idle4、idle10、AngleX -20/+20、AngleZ -10/+10、BodyAngleX -10/+10 の順に 0、15、10、0、0、47、81、13、7。外輪郭や髪付近を含む画素差であり、目視では大きな新しい頭部の穴は見えないが、サブピクセル差と新規露出を全画素で分類できていない。境界の完全一致は未確認。
- Blink 単独を初期値から 60 Hz で5秒進めた左目値は 0.5782〜1.0。0.598〜0.602 の区間に採取点はなく、0.133〜0.137 に到達しなかった。6 Hz の画像では中点の灰色を捉えておらず、0.60 の遷移が実時間で見えるかは未確定。0.135 はこの実験では判定不能。自然動作動画も約4.1 fps なので短時間の異常を除外できない。

確定: p2lrt SHA-256 `bf47f43bc252cf0318ec11c50a9ae0292574cbd279961938524f5e5835728bd0`。MCP import と export は成功。v10k 同様 Idle / Talk の builtin seed は失敗したが motion modifier は生成された。動画は同一軌道 `normal-pair.mp4` と自然動作 `natural.mp4`、静止の時刻付き `contact.jpg`。自然動画は実時間の61枚を15秒へ均等配置した。

未確定・残件: 実 GPU や通常速度での Blink の見え方、短い切替区間の二重線、頭部境界の画素差の分類、色残りと原画との同一性、Owner の最終判断。採用を断定しない。push、PR、merge、配備は行っていない。

最終 Web 検証: `npm run typecheck`、`npm test`（4 files / 30 tests）、`npm run build` 成功。配信ディレクトリを使う Chromium で v11b ロード成功、比較リンク11件を確認。画像は各1.5 MB以下、動画は各8 MB以下。動画の長さはそれぞれ20秒、15秒。

## 担当(Opus)の最終判定

未受入の比較候補。比較画像 `static.jpg`・`eye-detail.jpg`・`mouth-detail.jpg`・`poses.jpg` を目視した。

- 改善: 目の線は v11a の点状の途切れが無くなり、v10k のぼけより鮮明。口は閉→少し開→開の 3 状態が単一の口形として切り替わり、0.05 刻みのシートで二重線は見えない（胸像で 13 案かけて出せなかった点）。閉眼も線として閉じる。
- 新しい問題: 頬と髪の境に階段状の段差があり、左頬に切れ込み、右頬に矩形の段が残る。顎も左右が直線的で角張る。顔の矩形を広げた結果、顔が v10k より広くなり、前髪・横髪の内側の切断線が見えたと考える（原因は未検証）。
- 残件: 目の切替中点の灰色、0.15→0.10 の急変、閉口線の黄緑。目の形は原画より横長（素材の特性）。
