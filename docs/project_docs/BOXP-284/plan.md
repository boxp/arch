# BOXP-284: ひとはこ hero の表情を維持し、三つ編み・背後リボンの本数と接続を設定どおりへ修正

対象: `apps/hitohako`（stage: hitohako-stage.b0xp.io のみ。本番・共有インフラ・認証 policy は変更しない）

## 背景

BOXP-283 の hero（小さく口を開いた温かな笑顔）は雰囲気が好評だったが、髪と衣装の構造がキャラクター設定とずれていた。

1. 三つ編みが 3 本（向かって右側に内側・外側の 2 本）になっていた。設定は左右 1 本ずつ計 2 本。
2. 背後の帯リボンから垂れる長い帯が 3 本（左 2 本・右 1 本）になっていた。設定は左右 1 本ずつ計 2 本。

## 方針

- 今回の表情・顔立ち・柔らかい雰囲気・片手を胸に添えた所作・画風・色・表示サイズは維持し、髪と帯の構造だけを直す。画像全体をゼロから描き直さない。
- 制作: Nano Banana Pro（`gemini-3-pro-image`）の画像編集に BOXP-283 の hero（公開済み）を入力し、「向かって右の外側三つ編みを根元から毛先まで除去し周囲のストレートな長髪で埋める」「左の余分な垂れを除去し、結び目から左右 1 本ずつの長い垂れにする」「それ以外は変えない」と指示して複数候補を生成。顔アップ・全身・根元から先端の拡大比較で原画と照合し、表情と目の色が最も保たれた候補を採用する。
  - Gemini はマスク指定の inpainting ができず、カンバス全体を再描画する。線が数 px ずれるため、採用判断では顔・手・衣装・武器・透過境界に新しい破綻がないことを目視で確認する。
- 透過化と内容ハッシュ付きファイル名は既存の `scripts/make-hero.py` を使う。`src/lib/hero.ts` が build 時にファイル名を解決するため、`<picture>` の WebP / PNG と `<link rel="preload">` は自動で同じ revision を指す。`_headers` の immutable ルールはハッシュ付き名にマッチするので変更不要。
- 右の垂れが外へ流れなくなり透過画像の幅が変わる（1038x1600 → 885x1600）ため、README と global.css の寸法コメントを更新する。

## 不変更

配信アーカイブ 6 件・章順・既反映文言・静的表示・STG 記録・仲間・他キャラ・表示サイズ CSS・本番・認証 policy・他インフラ。
