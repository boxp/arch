# BOXP-663: kohako-home を開き直した後のモデル非表示と白い領域を修復する

## 報告
スマホ横向きで家を開き直すと、左側に大きい白い矩形がありコハコが表示されない（接続状態・時計・利用枠・入力欄は表示）。

## 調査結果
- 家の動く姿は WebGL（p2l.js）で描くが、`webglcontextlost` / `webglcontextrestored` を一切扱っていなかった。
- スマホは開き直し（バックグラウンドからの復帰）や GPU メモリ逼迫で WebGL のコンテキストを捨てることがある。家の canvas は DPR 2 以上固定・上半身枠では 3479×2883 px 級で、レイヤー用の描画先も同じ大きさで複数持つため、捨てられやすい。
- 修正前 main（3b02396）の実ブラウザで `WEBGL_lose_context` により喪失させると、canvas は空のまま表示され続け、静止画（`#face`）にも切り替わらず、コハコは再読み込みまで消えたままになる。`restoreContext()` しても既定の動作を止めていないため戻らない。他の UI はそのまま残り、報告の見え方（キャラだけ消える）と一致する。
- 失われた canvas がどう塗られるかはブラウザ依存（Chromium では透明）。報告の白い矩形は canvas の範囲（左右の余白込みで吹き出しの左側にかかる）と一致するが、iOS 実機での白表示はこの環境では再現できない（未確認）。

## 方針
1. `webglcontextlost` で既定の動作を止め（復帰を許可）、すぐに古いプレイヤーを止めて解放し、canvas を隠して既存の静止画へ切り替える（白い/空の canvas を残さない・コハコを消さない）。
2. `webglcontextrestored`、または画面に戻った時（`visibilitychange`・`pageshow`）にコンテキストが使えれば、同じ canvas へ動く姿を読み直し（演技の舞台・テクスチャの補正も作り直し）、終わったら動く姿へ戻す。
3. イベントの取りこぼしに備え、画面に戻った時にコンテキストの状態を確かめる。読み直しの途中でまた失われた時は結果を捨てる。状態遷移は `src/home/glloss.ts` に分け単体テストする。
4. `loadRig` は読み直しのために、付けた監視（枠切替・ResizeObserver）を外してプレイヤーを解放する `release()` を返す。

## 保護するもの
モデル・絵柄、会話・ふれあい・背景・利用枠・位置非保存、BOXP-658 のキュー・BOXP-657 の共通 backend。素材の再生成・モデル変更はしない。

## 検証
- `verify/home/context663.mjs`: スマホ横向き・PC・復帰なし・非表示中の喪失の 4 通りで、喪失中も姿が見え（静止画）、失われた canvas を表示し続けず、復帰後は動く姿に戻ることを判定。修正前は全項目で失敗、修正後は全項目成功。
- web の typecheck / biome / vitest。
- 配備後に配備版で同じ検証。
