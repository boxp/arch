# BOXP-626: kohako-home のレイアウト変化時の点滅・描画崩れを直し自然に遷移させる

## Owner 指摘

「kohako-home のレイアウトが動いた時（発言後など）に激しく背景が点滅したり壊れたようにみえるので、自然にトランジションするようにしたい。画面サイズが変わったときも不自然かも」

## 調査（最新 main 4bbb6e665 の build、BFF モック、Playwright の screencast 全フレーム）

- 場面（くつろぎ/おしゃべり/作業中/見せる…）や画面の形が替わると、`.character` の `left/width/height` が 0.3 秒の CSS transition で動く。
  リグの WebGL canvas は要素の大きさに合わせて描画バッファを作り直す（p2l.js `draw()`、DPR は 2 以上に固定）ため、遷移の間は毎フレーム作り直しになる。
  PC の上半身枠では 3479×2883 px（約 40MB/バッファ）。
- 全身/上半身の枠（`data-frame`）は即時に替わるのに箱だけ 0.3 秒かけて動くため、作業中へ入る時は一瞬巨大に描かれてから縮み、
  作業中から戻る時は一瞬小さく描かれてから伸びる（フレーム差分で 20 前後の飛びが 2 回続く）。これが「壊れたように見える」。
- 背景そのものの明滅は headless（swiftshader、GPU なし）では再現しなかった。実機 GPU で大きな canvas の毎フレーム再確保が重なると、
  合成時のメモリ逼迫で背景のタイルまで描き直しになり明滅に見えることがある、という仮説（未確認）。

## 方針

- リグ表示中は `.character` の CSS transition を止め、配置替えは 1 回で行う（canvas の作り直しは配置替えごとに 1 回）。
- 配置替えの直前に最新の姿勢で描いた絵を 2D の写し（画面解像度まで縮小）として元の位置・元の見える範囲に残し、
  0.24 秒で溶かしながら新しい絵を浮かび上がらせる（`src/home/morph.ts`）。写しを取るのは配置の組（場面・形・枠・小窓・表示欄・高さ）が
  替わった時で、さらに枠が替わったか canvas がひと息に 4% を超えて動いた時だけ。ウィンドウを少しずつ広げる操作では写しを作らず追従させる。
- 動きを減らす設定・OS の reduced-motion・非表示タブ・転送ゲートの出入りの間は写しを使わず即時に切り替える。
- 背景（月窓の間）の構図・動き・時間帯、コハコの見た目、会話/入力/スクロール/接触の挙動は変えない。

## 検証

- 単体: `morph.test.ts`（写すべき変化の判定、配置の鍵、写しの位置と見える範囲、無効時・小変化時、連続した替わり、CSS）。
- 実ブラウザ: `verify/home/layout626.mjs` で修正前/修正後の build を同じ手順で測り比べる（点滅セル、急な飛び、canvas の作り直し回数、写し）。
- 配備後: 実ロード版（kohako-home.b0xp.io）で実際の発言と viewport 変更を行い、時間変化を screencast で確認する。
