# BOXP-646: kohako-home の選択肢を一貫した返信ボタン表示へ統一する

## 背景・原因

選択肢がボタンになる／ならないが混在していた原因は 3 つ。

1. 通知の選択肢抽出（`docker/codex-workspace/task-board/task_board_events.bb` の `extract-choices`）が行頭の `A)`・`A：` 型だけに対応し、
   `A（推奨）：`・`A「…」`・`**A**：`・`1. …`・`B1／B2`・1 行併記の `A：…／B：…`（BOXP-644 の通知で実際に発生）を落としていた。
   配信済み通知 239 件で確認。
2. 家の通知吹き出し（`main.ts` の announce）は選択肢があると自由文欄を出さなかった（BOXP-568 は受信箱だけ修正）。
3. 通常会話の返答には選択肢ボタン自体がなかった。

## 方針

- 共通の抽出規則 `choices.ts` を作り、`web/src/home/choices.ts` と `bff/src/choices.ts` を同一内容に保つ（bff テストで照合）。
  - 対象: 行頭（箇条書き・太字可）の `A：`/`A）`/`A.`/`A「`/`A（`、`1.`、`B1`、1 行併記 `A：…／B：…`。A（または 1）から連番 2〜6 個。
  - 数字・`B1` 型は、本文に「どれ／どちら／どの／選ん／選択」等があるか、項目に「推奨／おすすめ」があるときだけ（手順・確認項目の番号を除外）。
  - 対象外: 連番でない・1 個・7 個以上・上記条件を満たさない番号付き箇条書き・承認（許可／拒否）UI。
- BFF: 通知に `choices` がなければ本文から補完（ingest 時に保存、変更前に保存済みの通知も一覧時に補完）。返信の検証も同じ規則。送る値は記号（A など）のまま。
- 受信箱・通知吹き出し: ボタンは「A：説明」表示、送る値は記号。吹き出しも自由文欄を常に併設。既存の event 単位の送信ロック・replyId 再送は維持。
- 会話: 最新の返答に選択肢があれば吹き出し下にボタン。押すと「1：説明」を通常の発言と同じ経路（受理未確認の確認・送信待ちを含む）で送る。押した時点で閉じて二重送信を防ぎ、下書きは消さない。返答が変わる（次の発言・別の返答）と閉じ、古い返答へ結び付けない。承認 API は使わない。

## 検証

- web/bff の型検査・Biome・単体テスト（抽出規則は実通知の書き方を網羅）。
- `verify/home/choices646.mjs` で PC・Pixel 7 の実ブラウザ検証（BFF モック）。
- merge 後、通常配備（image build → Image Updater → Argo）された版で同じ検証と BOXP-568 の回帰。

## 対象外

許可／拒否の安全境界、task_board_events.bb の抽出規則（BFF 側で補完するため変更しない）、Studio 画面。
