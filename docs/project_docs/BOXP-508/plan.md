# BOXP-508: kohako-home で応答待ち中の追加発言を送信待ちに積み、順に送る

## 目的
コハコの応答・ツール処理を待つ間も次の発言を入力して「キューに追加」でき、現在の依頼が正常に終わってから FIFO で 1 件ずつ同じ Web 会話へ送る。現在の run を中断・並列化しない。

## 方針（責務）
- 家の画面（`web/src/home`）だけで実装する。BFF は既に pending 中の新規送信を `busy` で拒否するため、キューはクライアントで持ち、送信は既存の送信経路（受付番号・受理未確認の控え・冪等再送）を再利用する。
- Hermes 側の変更・mid-turn 割込・並列 run・新しい権限は使わない（通常の新規メッセージを順に送るだけ）。

## 仕様
- `queue.ts`: `MessageQueue`（最大 5 件・各 500 文字、追加・取消・先頭取り出し・先頭へ戻す・保留/再開）。純粋ロジックで単体テスト。
- 応答待ち中（または送信待ちが残る間）の送信は送信待ちへ積む（ボタンは「キューに追加」）。積めないとき（上限・長すぎ）は入力欄の本文を消さない。
- 送信待ち欄: 順番・未送信表示・個別取消・すべて取消・状態（いまの応答後に送る／保留理由）・再開。サーバー受理（202）までは履歴に「あなた」として出さない。
- 自動送信は直前の依頼が `done`（読み上げ/口パク終了後）または待機中のときだけ。失敗・停止・承認期限切れ（失敗）・認証切れ・未接続・送信成否不明では保留し、明示の「再開」を待つ。
- 成否不明（5xx・通信失敗）は既存の受理未確認の控え（同じ受付番号）に残し、送信待ちには戻さない（二重送信防止）。再開で照会→受理済みなら追跡、未受理なら同じ受付番号で再送。
- 承認・拒否・停止は進行中の run への独立操作のまま。送信待ちの「A」「OK」などは承認の回答として使わない（承認ダイアログ表示中は送らない）。
- 通知返信の追跡（BOXP-501）は通常の送信待ちと別の受付番号で、本文を結合しない。
- 連打・Enter: 積んだ時点で入力欄を空にするため同じ本文は二重に積まれない。送信中フラグで先頭を 1 度だけ取り出す。IME 変換中（`isComposing`/keyCode 229）の Enter は無視。
- 再読み込み: 送信待ちの本文はメモリのみで保存しない（再読み込み・タブを閉じると消え、自動再送しない）。消える前に `beforeunload` 確認を出す。送り出し中の 1 件だけは既存仕様どおり受理未確認の控え（sessionStorage）で追跡する。
