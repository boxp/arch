# BOXP-481: サンライズ監視の受付時間外抑止

## 計画・実装

- JST 01:50 以上 05:30 未満は getter を呼ばず無出力で終了する。23:30 は時刻のみでは閉館としない。
- 各照会直前と最終照会後にも時計を確認し、tick 中に閉館した場合は途中の観測・通知・失敗記録を確定しない。
- 公式応答 20100941 を受けた場合、残りを照会せず、次の 05:30 JST を `closed_until` に保存する。既存の lock と atomic state 書き込みを使用し、期限到達後の通常 tick で自動解除する。
- 閉館時は既存の部屋状態、観測時刻、last-good、障害・通知履歴を保持する。混雑 20100946 と HTML 欠損は従来の障害として扱う。

## 検証結果

- `python3 -m unittest discover -s tests/sunrise -v`: 25 件成功。隔離時計・getter で境界、UTC/JST、日跨ぎ、23:30、途中閉館、公式応答による永続化・再起動・解除、再開後の空席/満席/不明・重複抑止と既存履歴保持を確認。
- 追加検証では先頭の公式受付外応答で残り7検索を中止し、最終照会中の01:50跨ぎでも無出力・履歴保持、再開後のtimeoutの失敗加算と通常障害通知を確認。main入口からstate保存・再起動・05:30解除まで検証した。
- 外部サイトへのアクセスや本番環境の変更は実施していない。実際の閉館 tick と 05:30 再開は配備後に確認が必要。

- 私的な現行設定・state・取得済み公式受付外HTMLを使い、旧mainと修正版を隔離比較した。通常閉店時のgetter呼出は8→0、通常受付内に受付外応答が出た場合は8→1となり、修正版はいずれも無出力・既存観測/障害/通知履歴不変。生HTMLと設定は公開しない。

- Trivy v0.76.2で全体config走査を完了した（チェックbundleの取得が進まないため同梱チェック使用）。既存インフラ/Dockerfileの検出は残り、本変更でDockerfile・インフラ設定は変更していない。

## 統合・配備

既存 CI は sunrise テストを実行し、Hermes image に `sunrise/` をコピーする。通常のレビュー・CI・マージ後、既存の正規 Hermes image 配備経路で反映し、実効 revision を確認する。実閉館 tick の外部照会ゼロと無出力、翌 05:30 以降の通常 tick の再開を確認する。未到達の時刻は隔離試験の結果と実環境の未確認を区別する。state の手動編集や scheduler の無効化は行わない。
