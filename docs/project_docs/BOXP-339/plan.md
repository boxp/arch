# BOXP-339: ひとはこ Hero の三つ編みを左右各 1 本へ局所修正

対象: `apps/hitohako`（stage: hitohako-stage.b0xp.io のみ。本番・認証 policy・他インフラは変更しない）

## 目的

BOXP-293 で採用した Hero 画像（`hitohako-hero-dabaed482e`）は、三つ編みが向かって右（本人の左）の 1 本しかなく、向かって左はストレートの髪だった。キャラクター設定では三つ編みは左右に 1 本ずつなので、Owner の承認を受けて向かって左に 1 本足す。全体の再生成はしない。

## 方法

- 顔周辺を切り出し（x700–1420, y0–900）、Gemini（`gemini-3-pro-image`）で「向かって左に、既存の三つ編みと同じ太さ・編み目・色の三つ編みを 1 本足す」よう編集した。3 候補のうち、根元から結び・毛先までが最も自然な候補 2 を採用した。
- 採用候補の向かって左の髪領域だけを、ぼかしたマスクで元画像に合成した。顔・表情・既存の三つ編み・衣装・背景は元の画素のまま。
- 元 JPEG と同じ量子化テーブル・サンプリングで再保存し、`scripts/make-hero.py` で content-hash アセット `hitohako-hero-570eabbe64{.jpg,-960w/-1440w/-2560w.webp}` を出力した。旧 `dabaed482e` は削除した（URL が変わるため、旧画像が cache から配信されることはない）。
- CSS・レイアウト・`hero.ts`・肩書・配信一覧・認証は変更しない。

## 検証

- 画素差分（旧 JPEG と新 JPEG のデコード後）: RGB 差が 8 を超える画素は bbox (729,245)–(933,633) の中だけ（向かって左の髪のみ）。それ以外の差は JPEG を再保存したことによる最大 8 程度のごく小さな差だけ。顔領域の平均差は 0.03。
- 目視（拡大）: 新しい三つ編みは、向かって左のサイドの髪の中から頬・首の脇を通って鎖骨の高さの小さな結びまで伸び、その先に短い毛先が続く。分岐・合流・編みかけの部分はない。既存の右の三つ編みは変更なし。
- `npm run build` は成功。`dist/index.html` の Hero 参照は新しい hash だけで、旧 hash の参照は 0 件、初期表示の iframe は 0。

## Rollback

この PR の squash commit を revert すると `hitohako-hero-dabaed482e` に戻り、deploy-hitohako.yml が stage を自動で更新する。
