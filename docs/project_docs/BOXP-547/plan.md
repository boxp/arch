# BOXP-547: 受信箱更新時に入力中の返信が消える不具合の修復

## 原因
`apps/kohako-studio/web/src/home/inbox.ts` の `render()` は一覧更新（60秒ごとの定期更新、案内処理、既読化・処理済み操作など全ての `refresh()`）のたびに
`detail.replaceChildren()` で詳細欄を作り直し、返信用 `textarea` も新しい空要素に置き換えている。
そのため新しい通知が届いた・既読状態が変わった等のタイミングで、入力中の本文・フォーカス・IME 変換中の文字が失われる。

## 方針
1. 返信の下書きを通知 ID ごとに保持する（`drafts: Map<eventId, string>`、`input` イベントで更新）。
   - 別の通知を選び直しても、その通知の下書きだけが表示される（別通知への誤送信防止）。
   - 送信成功時にその通知の下書きを破棄する。
2. 詳細欄は「選択中の通知 ID・題名・本文・出どころ・選択肢・返信状態」が変わらず、表示待ちのお知らせ文（notice）も無い場合は作り直さない。
   メタ行（経過時間・既読/処理済み）だけ更新する。これで textarea 要素そのもの・フォーカス・選択範囲・IME 変換中の状態が保たれる。
3. 作り直しが必要な場合（別通知選択・返信状態の変化など）は下書きを復元し、元の textarea にフォーカスがあればフォーカスと選択範囲も戻す。
4. 返信ボタンは表示中の通知 `i` と、その通知の textarea の値だけを送る（既存動作の維持）。

## 検証
- vitest: 下書きの保持・通知ごとの分離・送信後の破棄のユニットテスト。
- `verify/home/inbox547.mjs`（BFF 完全モック・Playwright）:
  入力中に通知追加/既読変化で一覧更新 → 本文・フォーカス保持、別通知へ切替→空欄、戻る→下書き復元、
  返信送信先が正しい通知 ID で本文一致、送信後は返信済み表示。修正前ビルドで再現（失敗）すること、修正後で全 PASS を確認。
- typecheck / vitest / build。
- merge 後、配備 image の静的資産で inbox547 を再実行。証跡は `/home/boxp/verification-artifacts/BOXP-547/`（vault 保存なし）。
